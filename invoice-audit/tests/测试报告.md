## 4. ③ 压力测试（locust，40 并发 90s，4999 请求 0 失败）

| 接口 | 请求数 | 失败 | 中位 | p95 | p99 | 吞吐 |
|---|---|---|---|---|---|---|
| GET /api/health | 1802 | 0 | 1ms | 3ms | 5ms | 20.1/s |
| GET /api/enums | 1301 | 0 | 1ms | 4ms | 5ms | 14.5/s |
| GET /api/claims/mine | 877 | 0 | 4ms | 9ms | 13ms | 9.8/s |
| GET /api/dashboard/stats | 350 | 0 | 5ms | 9ms | 12ms | 3.9/s |
| GET /api/dashboard/tables | 109 | 0 | 9ms | 15ms | 17ms | 1.2/s |
| POST /api/auth/login | 450 | 0 | 87ms | 130ms | 150ms | 5.0/s |
| GET /api/monitor | 110 | 0 | **510ms** | 560ms | 560ms | 1.2/s |
| **合计** | **4999** | **0** | 2ms | 90ms | 510ms | **55.7/s** |

**分析与处置：**
- 登录 87ms 中位 = pbkdf2(60 万轮) 的**有意安全成本**（5 次/秒/进程无压力），保留。
- **/api/monitor 510ms 热点**：`psutil.cpu_percent(interval=0.5)` 每请求阻塞 0.5s。→ **已修复**（非阻塞采样 + 2s 响应缓存），复测：首呼 138ms、后续 **2ms**（↓99.6%）。
- 0 失败、0 重试风暴，状态机与数据库在并发下稳定。

## 12. 已知限制与建议

1. 登录 87-110ms（pbkdf2 安全成本）——高并发登录场景可评估 bcrypt/argon2 或前置限流网关
2. 单 OCR worker 串行（21 张/分钟）——扩容 `OCR_WORKERS=2` + uvicorn 多 worker + MySQL 连接池
3. LLM 判定存在波动（同票两次判定可能不同）——建议对"报销"结果加人工抽检比例
4. UI 测试基于本机 Edge；未做多浏览器兼容矩阵（可后续扩 Firefox/WebKit）

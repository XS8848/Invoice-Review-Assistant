## 4. 核心模块原理

### 4.1 状态机（workers/dispatcher.py）
- 轮询 `queue_state=1 且 flow_status in (1,2)`，**原子领取**：
  `UPDATE claims SET queue_state=0, lock_owner=?, lock_acquired_at=NOW() WHERE id=? AND queue_state=1`（rowcount==1 才算抢到）
- 租约回收线程每 60s 把 `lock_acquired_at < NOW()-10min` 的锁重置回 queue_state=1（worker 崩溃自动救回）
- OCR 线程池 1 并发（GPU 串行），LLM 线程池 2 并发；`.env` 的 `OCR_WORKERS/LLM_WORKERS` 可调

**状态转移表（8 迁移）**：
| 事件 | 前态 | 后态 |
|---|---|---|
| 员工提交 | — | flow=1, queue=1 |
| 视觉领取 | flow=1, queue=1 | queue=0 |
| 视觉成功 | flow=1 | flow=2, queue=1（ocr_text/conf 落库） |
| 视觉置信度低/关键字段缺失 | flow=1 | flow=3, exception=1, queue=1 |
| LLM 领取 | flow=2, queue=1 | queue=0 |
| LLM 判定 0/1 | flow=2 | flow=0, queue=2, result=0/1 |
| LLM 无法判断 | flow=2 | flow=3, exception=2, queue=1 |
| 人工判定 | flow=3 | flow=0, queue=2, reviewer_note |

### 4.2 视觉识别（services/ocr_service.py）
- 引擎单例：`PPStructureV3(lang=ch, device=gpu:0, 关闭图表/公式/印章识别)`；CPU 模式必须 `enable_mkldnn=False`（paddle 3.3 bug）
- **PDF 双通道**：pymupdf 抽文本层（born-digital 权威）→ clean_fields；无文本层则渲染 PNG（200dpi）走 OCR
- 大图防 OOM：边长 > `max_side`(默认1600) 用 PIL 缩放
- 结构依据（实测）：`result.json["res"]["overall_ocr_res"]` 含 `rec_texts/rec_scores/rec_polys`
- **清洗 clean_fields**：发票类型→号码（发票号码/No/20位）→代码（10位按行）→日期→购销方（值式成对解析：公司行+15-20位税号行，剔除银行行）→金额税额（按大小修正 OCR 顺序颠倒）→税率→开票人（排除购销方名与纯大写数字行）→品名（`*服务*` 特征段+表格区）
- **置信度聚合**：过滤噪声行（<2字符/纯符号/短数字串）后 `conf = 0.8*avg + 0.2*min`，阈值 0.75（调参页可改）

### 4.3 语言模型（services/llm_service.py）
- 固定两轮：第1轮 `tool_choice` 强制 `get_claim_info`（服务端回填单据信息）→ 第2轮强制 `submit_verdict`
- **必须 `"thinking":{"type":"disabled"}`**：deepseek-flash 默认思考模式不支持强制 tool_choice 且耗 token
- 工具参数服务端强校验（result∈{0,1,2}）；任何异常重试 1 次 → 兜底 result=2（转人工，不丢单）

### 4.4 规则引擎（services/rules.py）
确定性规则按序执行（全部用代码计算，可解释）：
1. 票面完整性（号码/日期/价税合计缺失→不报销）
2. 重复报销（同发票号已有 result=0 记录→不报销）
3. 有效期（默认365天；未来日期拦截）
4. 抬头校验（个人/与公司主体不符→不报销）
5. 金额算术（金额+税额=价税合计）
6. 税率白名单（非常规→预警）
7. 敏感品类（无备注→不报销；有备注→预警交 LLM）
8. 限额（单笔超限→人工；月累计超限→按 `per_month_limit_action` reject/review）

规则命中 `hard_fail` 且 `hard_fail_skips_llm=true` 时**跳过 LLM 直接不报销**（省 token、结论可解释）。

### 4.5 存储（services/minio_service.py）
- 内部客户端连 `MINIO_ENDPOINT`（127.0.0.1:9000）做上传下载
- 预签名用**对外地址**：`presigned_url_for_host(object_key, host)` 按请求 Host 自适应——localhost/127.0.0.1→`127.0.0.1:9000`；IPv4→`同IP:9000`；域名→`MINIO_PUBLIC_ENDPOINT`
- 原图接口返回 **JSON `{"url":...}`**：前端必须经 axios（带 JWT）取 URL 再加载——`<img>/<iframe>` 直连不带凭证会被 401（本项目修过的坑）

### 4.6 调参热更新（runtime_config.py）
- 四区块默认值 `DEFAULT_CONFIG` → 启动时 `load_runtime` 用 configs 表覆盖合并 → 内存 `_runtime`
- `set_section`：合并默认→写 DB→更新内存，worker 每次任务执行时 `get_section()` 读最新值（即时生效）

## 8. 前端开发

- 结构：`router.js` 懒加载 7 页面；`api.js` axios 拦截器（注入 JWT、401 跳登录、统一报错）

- 构建：`npm run build` → dist 由后端 StaticFiles 托管（SPA fallback 回 index.html）

## 11. 已知坑（沉淀，继承到二次开发）

1. paddleocr 返回结构在 `result.json["res"]["overall_ocr_res"]`；空行 rec_score=0 必须过滤
2. deepseek-flash 默认思考模式：强制 tool_choice 报 `invalid_request_error` → 必须 `"thinking":{"type":"disabled"}`
3. minio SDK 7.x `presigned_get_object` 的 `expires` 参数要 `timedelta`（传 int 会 AttributeError）
4. MySQL 标识符用方言感知引号（`identifier_preparer.quote`），双引号在 MySQL 是字符串
5. OCR 税号提取不能压平全文（发票代码+号码会粘连）；按行匹配并剔除含"银行/开户行"的行
6. Pydantic v2 缺 `from_attributes=True` → `model_validate(ORM)` 500
7. PowerShell→wsl 传参引号/`$()` 必炸 → 一律写 .sh + `tr -d '\r' | bash`
8. `pkill -f` 的匹配串若出现在外层 bash 命令行里会连包装进程一起杀 → 用脚本文件 + `pkill -x`
9. `psutil.cpu_percent(interval=0.5)` 每请求阻塞 0.5s → `interval=None` + 响应缓存
10. 前端 `<img>/<iframe>` 直连 API 不带 JWT → 401；必须先 axios 取预签名 URL
11. axios 上传 FormData 手动设 Content-Type 会丢 boundary
12. Playwright Chromium 官方 CDN 被重置 → 用 `channel:'msedge'`（本机 Edge）
